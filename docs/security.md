# Security / access control

## Threat model and boundaries
Untrusted browser, guessed object IDs, manipulated DTO, role spoofing, replay/double submit, malicious cross-site request, leaked credentials, SQL injection, worker races, provider malformed responses. Not a real payments system, no real credentials. Local development over HTTP is allowed; deployment not required. Never imply formal security certification.

## Authentication
Local email/password, normalized email, bcrypt or Argon2id password hashes (choose and record parameters; no plaintext in DB/logs), generic invalid_credentials 401; test password only in local seed/README. JWT signed with high-entropy env secret, explicit algorithm/issuer/audience/exp, short TTL (e.g. 30 minutes), claims sub + sid (no authority from roles in JWT), HttpOnly cookie `renewaldesk_session`, path `/`, SameSite=Lax or Strict (choose Strict by default), Secure true for HTTPS deployment; false only documented local HTTP. No JWT in localStorage, no access token in JSON. DB auth_sessions (sid, user, expiry, revoked_at); authenticate verifies signature/claims, expiry, session and active user; load membership/roles server-side on every authorized request. Logout revoke sid and clear cookie; repeated unauthenticated logout may return 204 only if intentionally documented (default require valid session for 204; otherwise 401). No registration/SSO/refresh needed; 401 UI returns login. Login rate limit by IP+normalized account (avoid leaking existence), bounded body sizes, Helmet/security headers, no broad CORS. Env secrets generated for local/testing, never commit real secret; `.env.example` placeholders, fail startup for missing/weak config except explicit local test config.

## CSRF (chosen implementation)
Same-origin browser (Nginx routes API/docs). Require exact allowed Origin on all unsafe endpoints including login; curl/test clients send Origin explicitly. Never accept arbitrary Origin or wildcard credentialed CORS. Authenticated unsafe requests (logout/create/approve/reject/retry) additionally require `X-CSRF-Token` from authenticated GET `/api/v1/auth/csrf`; token derived via HMAC with separate server secret and session ID (e.g. HMAC-SHA256(secret, "csrf:" + sid), base64url), constant-time compare, token bound to valid session. Do not expose token via logs/URL/cookie auth secret; browser stores token in memory and refetches after reload/login. GET safe, no mutations. Login protected by strict Origin and rate limit, no pre-session token required. CSRF error 403 `csrf_invalid`, origin 403 `origin_forbidden`. Document same-origin Stoplight/Swagger calls with cookie + CSRF header; verify browser Try It or clearly document manual header workflow. No auth bypass for API docs. CSRF token endpoint no-store.

## Authorization matrix
| Action | Initiator | Approver | Both |
|---|---|---|---|
| overview/read resources/requests/audit | own space | own space | own space |
| create | yes | no | yes |
| approve/reject | no | other author's pending | other author's pending |
| retry attention | no | yes (own space) | yes (own space; only previously approved request) |

Server resolves entity ID and tenant safely: unauthorized request always 401 before data access; valid session lookup by ID allows distinguish nonexistent 404 vs known other workspace 403 (requirement), without returning object content. All list/aggregate/filter joins scoped to session workspace; if explicit foreign resource_id filter in audit, return 403 not leaked list. No client-supplied workspace_id/role/created_by/decided_by, prices/dates; strict DTOs reject unknown properties. Membership does not come from headers or localStorage. `GET /auth/me` returns only own info. API denies unauthorized requests even if UI hides controls. No global admin, impersonation, account switch or dataset reset endpoints. No quick-account selector is shipped; fictional credentials are documented for manual local login. Switching users requires logout + login. Bundled datasets refuse APP_ENV=production at runtime; seeders require explicit APP_ENV=development or test. NODE_ENV=production alone is used for the local optimized Docker image and does not enable public deployment. No customer access to provider directly through product endpoints.

## Data handling & hardening
Parameterized Sequelize/SQL binds (never string concat for filter/sort; allowlist columns/order). Validate path/query lengths, status/date/boolean/limit/offset, input body unknown fields and invalid types; HTML escape via React, avoid dangerouslySetInnerHTML. DTO whitelist + forbidNonWhitelisted, explicit serialized response fields (no password_hash, auth_session, token). Audit append-only via application, no delete/update public API. HTTP errors sanitized standardized envelope; no stack trace or raw provider response. Log only allowed metadata, redact Authorization, Cookie, Set-Cookie, password, JWT, CSRF and provider idempotency header; no full bodies by default. DB user not superuser for app where feasible, separate migrations user optional, DB/provider not public; network isolation and loopback exposed development ports. Non-root containers for API/web/worker/provider if practical, deterministic images, lockfile, dependency audit and document remaining findings. No unverified claims. See tests for permission denial, CSRF, cross-tenant list/detail/audit and role spoofing.
