# RenewalDesk — старт работы в Claude Code

Это комплект требований и референсов, а не готовое приложение. Исходная точка: отдельный Git-репозиторий, корень которого содержит этот файл, `CLAUDE.md`, `spec.md`, `docs/` и `references/`.

## 1. Подготовка

1. Распакуй архив в отдельный каталог проекта. Не оставляй второй вложенный уровень с `CLAUDE.md`: Claude Code нужно открывать именно корень с `CLAUDE.md`.
2. Установи Docker с Compose v2, Git и Node.js 22 (для локальных инструментов; основной запуск через Docker). Версии и совместимость зависимостей агент должен проверить и зафиксировать в lockfile и README. Это выбранная базовая версия, не требование использовать новейшие релизы.
3. При необходимости `git init` и первый commit с исходными документами. Не добавляй настоящие секреты или рабочие данные.
4. Запусти Claude Code из корня проекта. Вставь промпт из `PROMPT_FOR_CLAUDE_CODE.md`.

## 2. Источники и приоритет

- `references/company/task.pdf` — оригинал задания компании (8 страниц).
- `references/company/provider_simulator.py` — оригинальный провайдер, не изменять.
- `references/design/README.md` — handoff второй, принятой версии Claude Design; `RenewalDesk.dc.html`, `support.js`, `screenshots/` — утвержденная визуальная и поведенческая основа. Вложенный `task.pdf` совпадает с оригиналом.
- `spec.md` и `docs/` — инженерные решения владельца проекта и согласованное развитие требований. Если реализация handoff противоречит этим документам (например, имитация безопасности или способ рестарта), использовать инженерную спецификацию; если противоречит PDF — приоритет PDF.

## 3. Как работать

Начать с этапа 0 и 1 из `docs/implementation-plan.md`: изучение, короткая фиксация решений, scaffold и проверяемый Docker-пуск. Дальше проходить этапы последовательно; после каждого этапа обновлять `docs/progress.md`, запускать релевантные проверки и сообщать фактические результаты. Не ждать дополнительного подтверждения между уже согласованными этапами, но остановиться перед разрушительными/несогласованными изменениями или существенным конфликтом требований.

`spec.md` и `CLAUDE.md` уже подготовлены. Не генерировать их с нуля поверх этих файлов. Если Claude Code уточняет детали, он дополняет документацию, фиксируя решения и не удаляя исходные требования. Имя `spec.md` — specification; отдельный дублирующий `speck.md` не нужен.

## 4. Готовый результат

В итоге ожидаются исходники приложения, миграции и seeders, reproducible Compose, OpenAPI + Stoplight, тесты с реальной БД и предоставленным провайдером, README с командами и тестовыми аккаунтами, сценарий перезапуска, документация принятых компромиссов. Деплой в облако не требуется. Не публиковать репозиторий без решения владельца; исходные материалы задания могут быть непубличными.
